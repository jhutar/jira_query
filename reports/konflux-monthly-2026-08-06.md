# Team Konflux range monthly
* **Overview:** The team root-caused and fixed a perfscale analyzer bug that let 12+ hour resource-analysis runs silently return zero usable data, met a Critical-priority ServiceAccount migration deadline across every Konflux tenant namespace, and removed Horreum from the probe metrics pipeline in favor of direct PostgreSQL ingestion. The OOM/CrashLoopBackOff Jira automation kept maturing and was used to catch real incidents and push back on Red Hat Support's "transient" classifications with cluster evidence. RPM release-pipeline (signing) work and a Quay.io 100x-capacity risk assessment both progressed but remain open pending external teams.
* **What was done:**
  * Root-caused and fixed a bug in `analyze_resource_limits.py` where malformed PromQL (`{{...}}`) silently failed every metric query, causing multi-cluster runs of up to ~20 hours to end with "no data" instead of a clear error ([KONFLUX-15159](https://redhat.atlassian.net/browse/KONFLUX-15159), 3sp, [perfscale#83](https://github.com/konflux-ci/perfscale/pull/83)); also added an accessible-cluster count to run output ([perfscale#82](https://github.com/konflux-ci/perfscale/pull/82)).
  * Closed out compliance and probe-reliability work: completed the Critical-priority ServiceAccount migration/cleanup across all Konflux tenant namespaces ahead of the July 30 deadline ([KONFLUX-14970](https://redhat.atlassian.net/browse/KONFLUX-14970), 2sp); migrated continuous-performance-testing jobs off Horreum onto a direct PostgreSQL label-computation pipeline, cutting an external dependency out of the feedback loop ([KONFLUX-15036](https://redhat.atlassian.net/browse/KONFLUX-15036), 3sp); and pinned probe-template Tekton pipeline refs to commit SHAs, eliminating GitHub/GitLab `429` rate-limit failures caused by resolving `main` on every run ([KONFLUX-14479](https://redhat.atlassian.net/browse/KONFLUX-14479), 5sp, [konflux-probe-test-templates#145](https://github.com/rhtap-perf-test/konflux-probe-test-templates/pull/145), [ci-configs!624](https://gitlab.cee.redhat.com/redhat-performance/ci-configs/-/merge_requests/624)).
  * Shipped OOM/CrashLoopBackOff Jira-automation features — Support Case API integration, namespace-routing overrides, cross-project dedup, and comment-based duplicate detection ([KONFLUX-14973](https://redhat.atlassian.net/browse/KONFLUX-14973), 5sp / epic [KONFLUX-14299](https://redhat.atlassian.net/browse/KONFLUX-14299), [MRs !4](https://gitlab.cee.redhat.com/redhat-performance/konflux-oom-jira-automation/-/merge_requests/4)/[!5](https://gitlab.cee.redhat.com/redhat-performance/konflux-oom-jira-automation/-/merge_requests/5)/[!6](https://gitlab.cee.redhat.com/redhat-performance/konflux-oom-jira-automation/-/merge_requests/6)/[!7](https://gitlab.cee.redhat.com/redhat-performance/konflux-oom-jira-automation/-/merge_requests/7)) — and used it to verify a production kaexporter OOM fix (zero restarts since Jul 16) and to get MCO's kube-rbac-proxy-crio-ip restart bug confirmed as backported ([KONFLUX-11032](https://redhat.atlassian.net/browse/KONFLUX-11032) / OCPBUGS-74970). Also fixed several probe-stability issues: unauthorized Quay.io access blocking `konflux-perfscale-4-tenant` releases ([KONFLUX-14805](https://redhat.atlassian.net/browse/KONFLUX-14805), permanently resolved via [infra-deployments#13035](https://github.com/redhat-appstudio/infra-deployments/pull/13035)/[#13036](https://github.com/redhat-appstudio/infra-deployments/pull/13036)), a stale `repository-validator` admission policy causing PaC timeouts on stone-stg-rh01 ([KONFLUX-14784](https://redhat.atlassian.net/browse/KONFLUX-14784)), a shallow-clone-induced CI OOM in `tenants-config-test` ([KONFLUX-14890](https://redhat.atlassian.net/browse/KONFLUX-14890), 2sp, [konflux-release-data!20079](https://gitlab.cee.redhat.com/releng/konflux-release-data/-/merge_requests/20079)), and Enterprise Contract trust violations in probe/tenant runs ([KONFLUX-15147](https://redhat.atlassian.net/browse/KONFLUX-15147), 2sp).
* **What is moving:**
  * The Quay.io dependency-risk assessment for ~100x Konflux build growth is in review: a one-pager was finalized and shared with Quay-QE, but discussion is blocked until the assignee returns from PTO after Aug 16 ([KONFLUX-15081](https://redhat.atlassian.net/browse/KONFLUX-15081), 5sp).
  * OOM/CrashLoopBackOff sprint triage is in review, with the team pushing back — using fresh cluster evidence — on Red Hat Support's "transient" classification of kube-controller-manager/etcd crashes on stone-prd-rh01, where tenant event-volume saturation (rh-acs-tenant: 119K events) is still causing lease-timeout crash loops; 6 support cases remain open awaiting Red Hat's response ([KONFLUX-15216](https://redhat.atlassian.net/browse/KONFLUX-15216), 4sp).
  * Several efforts are in progress but externally blocked: RPM release-pipeline signing-service ownership discovery has identified the owning teams but not yet gotten monitoring/perf-testing answers ([KONFLUX-15253](https://redhat.atlassian.net/browse/KONFLUX-15253), 3sp); the ArgoCD Agent ScaleLab replication epic is waiting on bare-metal reservation approval ([KONFLUX-15125](https://redhat.atlassian.net/browse/KONFLUX-15125)/[KONFLUX-15130](https://redhat.atlassian.net/browse/KONFLUX-15130)); and an early caching-proxy experiment shows no speedup so far and is blocked on read access to the `caching` namespace ([KONFLUX-15199](https://redhat.atlassian.net/browse/KONFLUX-15199), 3sp).
